# SKILL&MCP 管理页面产品需求文档

> 文档类型：产品需求文档（PRD）  
> 文档状态：V1.0，基于当前前端原型实现整理  
> 更新日期：2026-06-11  
> 适用项目：ChatBI Skill + MCP 统一工作台  
> 前端目录：`web_frontend/`

## 1. 文档目的

本文档描述当前 ChatBI 工作台中与 Skill、MCP 相关的前端产品功能、页面结构、交互规则、数据模型、原型边界及后续真实服务建设要求。

当前产品将 Skill 相关体验拆分为两类：

1. **普通用户体验**：发现、安装、查看和使用 Skill，不暴露底层 MCP、Schema 与技术配置。
2. **系统管理体验**：面向产品管理员、AI 应用开发者和运维人员，管理 Skill 工作流、MCP 配置、依赖关系、测试与健康状态。

本文档以当前已经实现的前端页面为准，同时为后续接入真实管理 API、持久化和权限系统提供产品依据。

## 2. 产品背景

ChatBI 已具备 Skill + MCP 双层执行架构：

- Skill 负责识别业务意图、组织工作流和交付业务结果。
- MCP 负责执行模型调用、知识检索、N2SQL、SQL 查询、联网搜索等原子能力。

在仅通过代码和配置维护 Skill/MCP 时，存在以下问题：

- 普通用户无法了解系统提供了哪些能力，也无法主动安装和使用能力。
- Skill 的业务价值与底层技术结构混杂，用户理解成本高。
- 管理人员无法直观查看 Skill 工作流、MCP 依赖和运行状态。
- MCP 配置、Schema、健康检查和被引用关系缺少统一入口。
- Skill 与 MCP 的新增、测试、启停和问题定位依赖开发人员操作代码。

因此，产品需要在统一工作台中同时提供用户侧 Skill 产品体验和管理侧 Skill/MCP 运维体验。

## 3. 产品目标

### 3.1 核心目标

- 为普通用户提供清晰的“我的 Skill”和“Skill 商店”。
- 让用户理解 Skill 能解决什么问题、能交付什么结果，并可立即体验。
- 为管理员提供 Skill 工作流、MCP 配置和依赖关系的可视化管理页面。
- 统一 Skill 与 MCP 的状态、测试、启停和问题定位入口。
- 保留现有 ChatBI 智能问答主链路，并支持从 Skill 页面跳转到真实问答。

### 3.2 当前原型成功标准

- 用户能够浏览已安装 Skill、使用次数和 Skill 商店。
- 用户能够搜索、筛选、查看、安装和打开 Skill。
- 用户能够进入 Skill 展示详情，了解价值、示例和使用前提。
- 管理员能够查看 6 个内置 Skill 和 7 个内置 MCP。
- 管理员能够进入 Skill/MCP 详情，完成前端原型级编辑、测试、启停和健康检查。
- Skill 与 MCP 详情页面可以互相追踪依赖关系。

### 3.3 当前非目标

- 不提供生产级在线工作流发布系统。
- 不提供在线任意 Python 代码编辑或执行。
- 不实现多租户、组织和细粒度权限系统。
- 不实现真实 Skill 商店审核、版本发布、计费和市场运营。
- 不在前端保存或回显真实 API Key、数据库密码等敏感信息。

## 4. 用户角色

| 角色 | 主要诉求 | 主要页面 |
|---|---|---|
| 业务用户 | 使用已安装能力，发现更多 Skill，快速开始问答 | 我的 Skill、Skill 商店、Skill 展示详情 |
| 产品/运营管理员 | 管理 Skill 状态、描述、工作流和测试结果 | Skill 管理、Skill 技术详情 |
| AI 应用开发者 | 配置 Skill 工作流、MCP 参数和 Schema | Skill 技术详情、MCP 技术详情 |
| 系统运维人员 | 查看 MCP 健康状态、连接配置和影响范围 | MCP 管理、MCP 技术详情 |

## 5. 当前能力基线

### 5.1 内置 Skill

| Skill 标识 | 中文名称 | 用户分类 | 是否默认安装 | 核心能力 |
|---|---|---|---|---|
| `data_query` | 数据查询与分析 | 数据与分析 | 是 | 查询内部业务数据并生成图表与分析 |
| `data_web_compare_analysis` | 内部数据与联网分析 | 数据与分析 | 是 | 结合内部数据和公开市场信息分析 |
| `yoy_yoy_analysis` | 同环比分析 | 数据与分析 | 是 | 计算同比、环比和趋势变化 |
| `web_search_answer` | 联网检索问答 | 知识与检索 | 否 | 检索最新公开信息并保留来源 |
| `web_compare_analysis` | 联网对比分析 | 数据与分析 | 否 | 基于上下文补充竞品和行业对比 |
| `chat` | 智能问答 | 效率办公 | 是 | 日常知识和汽车专业问答 |

### 5.2 内置 MCP

| MCP 标识 | 中文名称 | 分类 | 核心能力 |
|---|---|---|---|
| `llm` | 大语言模型 | AI | 意图识别、生成、分析与回答 |

| `sql_executor` | SQL 执行器 | Database | 执行受限只读 SQL |
| `web_search` | 联网检索 | Retrieval | 检索公开网页信息 |
| `time` | 时间工具 | Utility | 获取指定时区时间 |
| `text_analysis` | 文本分析 | NLP | 摘要、情感与关键词分析 |

## 6. 信息架构与路由

### 6.1 一级导航

| 导航项 | 路径 | 定位 |
|---|---|---|
| 智能问答 | `/chat` | ChatBI 对话与结果页面 |
| 我的 Skill | `/skills` | 普通用户的已安装 Skill 工作台 |
| 系统管理 | `/admin/skills` | Skill/MCP 技术管理入口 |

### 6.2 Skill 用户侧路由

| 路径 | 页面 |
|---|---|
| `/skills` | 我的 Skill |
| `/skills/library` | Skill 商店 |
| `/skills/:skillName` | Skill 用户展示详情 |

### 6.3 Skill/MCP 管理侧路由

| 路径 | 页面 |
|---|---|
| `/admin/skills` | Skill 管理列表 |
| `/admin/skills/:skillName` | Skill 技术详情与配置 |
| `/admin/mcps` | MCP 管理列表 |
| `/admin/mcps/:mcpName` | MCP 技术详情与配置 |

### 6.4 用户侧与管理侧分离原则

- 用户侧强调能力价值、应用场景、安装状态和立即体验。
- 管理侧强调唯一标识、技术状态、工作流、MCP 依赖、Schema 和测试。
- 用户侧不直接展示 MCP、参数映射和原始 Schema。
- 管理侧不使用市场化文案替代技术信息。

## 7. 全局产品框架

### 7.1 应用壳层

所有页面使用统一 `AppShell`：

- 左侧为全局导航。
- 右侧为页面内容区。
- 导航支持展开和收起。
- 页面右上角展示当前产品模式提示。
- Chat 页面保持自身会话历史面板和对话区结构。

### 7.2 全局状态规范

| 状态 | 含义 | 建议 UI |
|---|---|---|
| 已安装 | 当前用户可直接使用该 Skill | 绿色标签 |
| 未安装 | 当前用户尚未安装 | 灰色标签 |
| 已启用 | Skill/MCP 可参与运行 | 绿色状态点或标签 |
| 已停用 | Skill/MCP 不参与运行 | 灰色状态点或标签 |
| 配置异常 | 缺少配置或校验失败 | 红色状态标签 |
| 草稿 | 尚未发布或启用 | 黄色标签 |
| 健康正常 | MCP 最近检查通过 | 绿色健康点 |
| 需要检查 | MCP 健康检查异常 | 红色或黄色健康点 |
| 未检查 | 尚无健康检查结果 | 灰色健康点 |

## 8. 页面一：我的 Skill

### 8.1 页面定位

“我的 Skill”是普通用户管理和使用已安装能力的首页。页面不承担完整商店浏览职责，核心问题是：

- 我已经安装了哪些 Skill？
- 哪些 Skill 最近使用最多？
- 如何搜索、筛选并打开某个 Skill？
- 如何前往 Skill 商店发现更多能力？

### 8.2 页面头部

页面展示：

- 页面标签：`MY SKILLS`。
- 标题：我的 Skill。
- 描述：管理已安装到 ChatBI 助手的能力，快速打开并开始使用。
- 轻量入口：浏览 Skill 商店 →。

商店入口使用标题旁的文字链接，不使用大面积推广卡片，避免抢占用户管理已安装 Skill 的注意力。

### 8.3 近 30 天使用次数

页面展示已安装 Skill 的使用次数排名：

- 使用横向排名条形图。
- 每行展示排名、Skill 名称、使用占比条和使用次数。
- 当前原型使用固定演示数据。
- 后续真实实现接入 Skill 调用统计 API。

图表价值：

- 帮助用户识别常用能力。
- 帮助管理员判断 Skill 使用活跃度。
- 为后续推荐、排序和下架决策提供数据依据。

### 8.4 已安装 Skill 列表

#### 标题信息

- 标题：已安装 Skill。
- 展示已安装总数。
- 展示当前筛选结果数量。

#### 搜索与筛选

- 按 Skill 名称、描述和价值点搜索。
- 按用户分类筛选。
- 支持按最近更新、最近安装和名称排序。

#### 卡片布局

- 桌面端当前采用一行四张卡片。
- 卡片与 Skill 商店使用相同的共享 `SkillCard` 组件。
- 两个页面的卡片视觉、状态、点击和操作按钮保持一致。

#### Skill 卡片信息

- Skill 图标。
- 用户分类。
- 安装状态：已安装。
- Skill 中文名称。
- 一句话价值描述。
- 两条核心能力价值点。
- 输出类型。
- 操作按钮：打开。

#### 卡片交互

- 点击卡片进入 Skill 用户展示详情。
- 点击“打开”进入同一个 Skill 用户展示详情。
- Hover 时卡片上浮并增强边框和阴影。
- 搜索或筛选后列表自然收缩，不保留固定空白区域。

## 9. 页面二：Skill 商店

### 9.1 页面定位

Skill 商店用于发现、理解和安装企业内部已审核能力。页面回答：

- 平台有哪些可用 Skill？
- 哪些 Skill 值得优先体验？
- 某个 Skill 能带来什么业务结果？
- 当前 Skill 是否已经安装？

### 9.2 页面头部

- 返回入口：返回我的 Skill。
- 页面标签：`ENTERPRISE SKILL STORE`。
- 标题：Skill 商店。
- 描述：浏览企业内已审核的工作流能力，并安装到 ChatBI 助手。
- 显示当前筛选结果数量。

### 9.3 精选推荐

- 桌面端一行展示三张精选卡片。
- 当前从标记为 `featured` 的 Skill 中选取前三项。
- 精选卡片使用更强的视觉层级和浅色渐变背景。

精选卡片展示：

- 分类精选标签。
- Skill 名称和一句话价值描述。
- 浮动 Skill 大图标。
- 大图标下方展示两条核心能力标签。
- 底栏展示图标、名称、输出类型和打开/获取按钮。

精选卡片交互：

- 点击卡片进入 Skill 用户展示详情。
- 已安装 Skill 显示“打开”。
- 未安装 Skill 显示“获取”。

### 9.4 全部 Skill

#### 搜索与筛选

筛选栏使用单行紧凑布局：

- 搜索框：搜索 Skill 名称、用途或场景。
- 分类选择：全部分类、数据与分析、知识与检索、效率办公。
- 安装状态：全部安装状态、已安装、未安装。

筛选下拉框不在控件上方额外展示字段标题，避免破坏单行布局。

#### 列表布局

- 桌面端一行展示四张 Skill 卡片。
- Skill 商店与“我的 Skill”使用同一个共享卡片组件。
- 卡片内容、视觉、状态和交互保持一致。

#### 安装状态

- 已安装：绿色标签，按钮为“打开”。
- 未安装：灰色标签，按钮为“获取”。
- 点击“获取”后，当前前端原型将 Skill 标记为已安装，并显示反馈提示。
- 安装状态当前仅保存在前端运行状态中，刷新后不保证持久化。

### 9.5 空状态

当搜索或筛选无结果时：

- 展示“没有找到匹配的 Skill”。
- 引导用户调整关键词或筛选条件。
- 后续可增加“一键清除筛选”操作。

## 10. 页面三：Skill 用户展示详情

### 10.1 页面定位

Skill 用户展示详情用于帮助普通用户理解和体验某个 Skill，不展示底层技术配置。

### 10.2 Hero 区域

展示：

- Skill 图标、分类和企业内部认证标识。
- Skill 名称和一句话价值描述。
- 安装状态。
- 主操作：立即体验或安装 Skill。
- 次操作：带着示例去提问。
- 输出结果类型和迷你图表预览。

### 10.3 能力价值

“这个 Skill 能为你做什么”区域展示 Skill 的核心结果价值。每条价值使用编号卡片表达，强调用户获得的结果，而非技术执行步骤。

### 10.4 ChatBI 演示

页面内置 ChatBI 问答演示：

- 展示示例问题。
- 展示可理解的业务处理阶段。
- 展示模拟分析结果和图表。
- 不暴露 MCP 名称和 Schema。

### 10.5 使用案例

- 展示 Skill 示例问题。
- 点击案例后跳转智能问答页，并将问题预填至输入框。

### 10.6 安装前检查

按 Skill requirements 展示使用前提，例如：

- 业务数据库只读权限。
- 联网搜索权限。
- 历史同期数据。
- 字段口径知识库。
- 已有对话上下文。

每项前提均说明用户需要完成的动作。

## 11. 页面四：Skill 管理

### 11.1 页面定位

Skill 管理面向系统维护人员，用于查看业务能力、技术状态、工作流步骤和 MCP 依赖。

### 11.2 Skill 管理列表

#### 页面指标

- Skill 总数。
- 已启用数量。
- 工作流步骤总数。
- 依赖异常数量。

#### 搜索与筛选

- 按中文名称、唯一标识和描述搜索。
- 按技术分类筛选。
- 展示当前结果数量。

#### 管理卡片

每张卡片展示：

- Skill 图标和状态。
- 中文名称与唯一标识。
- 技术描述。
- 分类和输出类型。
- MCP 依赖标签。
- 工作流步骤数量。
- 状态与最近更新时间。
- 查看详情入口。

#### 新建 Skill

当前“新建 Skill”按钮仅显示原型提示，尚未实现完整创建向导。

### 11.3 Skill 技术详情

页面包含四个 Tab：

#### 概览

- 唯一标识。
- 输出类型。
- 工作流步骤数量。
- 最近更新时间。
- 示例问题。
- MCP 依赖列表。
- 点击依赖 MCP 可进入对应 MCP 技术详情。

#### 工作流

- 使用纵向步骤列表表达执行顺序。
- 每个步骤展示序号、描述、步骤标识、绑定 MCP 和参数映射。
- 支持添加步骤。
- 支持步骤上移和下移。
- 点击 MCP 可进入 MCP 技术详情。

当前原型不实现复杂节点画布和真实拖拽连线。

#### Schema

- 展示输入字段。
- 展示 Skill 原始配置 JSON。
- 当前以 `query` 必填字段为基础原型。

#### 测试

- 输入测试问题。
- 运行 Skill 测试。
- 展示成功状态、执行摘要和步骤时间线。
- 当前测试结果为前端原型模拟，不执行真实管理测试 API。

### 11.4 Skill 状态与保存

- 支持前端原型级启用和停用。
- 支持保存配置提示。
- 修改仅更新当前前端内存状态。
- 刷新页面后不保证保留。

## 12. 页面五：MCP 管理

### 12.1 页面定位

MCP 管理用于查看和维护原子工具连接、Schema、健康状态和被 Skill 引用关系。

### 12.2 MCP 管理列表

#### 页面指标

- MCP 总数。
- 运行正常数量。
- 配置异常数量。
- 被 Skill 引用的 MCP 数量。

#### 页面操作

- 全部健康检查。
- 接入 MCP。

当前“接入 MCP”仅显示原型提示；全部健康检查会更新前端原型状态。

#### 搜索与筛选

- 按 MCP 中文名称、唯一标识和描述搜索。
- 按 MCP 分类筛选。
- 展示当前结果数量。

#### MCP 表格字段

| 字段 | 内容 |
|---|---|
| MCP 工具 | 图标、中文名称、唯一标识、描述 |
| 分类 | AI、Database、Retrieval、Utility、NLP 等 |
| 状态 | 已启用、已停用、配置异常 |
| 健康检查 | 正常、需检查、未检查和最近耗时 |
| 被引用 | 引用该 MCP 的 Skill 数量 |
| 来源 | 内置、本地或其他来源 |
| 操作 | 查看详情 |

## 13. 页面六：MCP 技术详情

### 13.1 概览

- 唯一标识。
- 健康状态。
- 最近耗时。
- 配置来源。
- 引用该 MCP 的 Skill。
- 近 24 小时调用成功率和执行次数。

点击引用 Skill 可进入对应 Skill 技术详情。

### 13.2 连接与配置

- 根据 MCP 类型展示连接配置。
- 敏感字段使用密码掩码，不回显真实值。
- 敏感字段仅支持覆盖更新。
- 支持前端原型级保存配置。

### 13.3 Schema

- 展示输入字段名称与类型。
- 展示标准返回契约：
  - `success`
  - `data`
  - `error`
  - `error_type`

### 13.4 测试与日志

- 根据 Schema 生成测试参数原型。
- 支持运行测试和健康检查。
- 展示成功状态、返回数据和耗时。
- 当前不提供历史日志持久化。

### 13.5 健康检查与启停

- 单个 MCP 支持健康检查。
- 健康检查完成后更新健康状态、耗时和更新时间。
- 支持启用和停用 MCP。
- 当 MCP 被 Skill 引用时，状态变更反馈会提示影响 Skill 数量。

## 17. 交互与反馈规范

### 17.1 卡片

- Skill 用户卡片必须复用共享组件，保持跨页面一致。
- 点击整张卡片进入详情。
- 操作按钮不得触发重复的父级点击事件。
- Hover 时上浮并增强边框和阴影。

### 17.2 搜索与筛选

- 搜索和筛选即时生效。
- 筛选后列表高度随内容自然变化。
- 无结果时展示明确空状态。
- 分类和安装状态筛选使用紧凑单行布局。

### 17.3 操作反馈

- 安装、保存、健康检查、启停等操作显示短时 Toast。
- 原型模式操作需要明确提示仅在当前前端状态生效。
- 测试成功展示绿色成功状态。
- 异常和依赖影响需要在真实 API 阶段提供明确原因。

### 17.4 页面滚动

- Skill 商店、我的 Skill、Skill 展示详情和管理页内容区支持独立纵向滚动。
- 左侧全局导航固定，不随内容滚动。

## 18. 安全与权限原则

- 普通用户只使用用户侧 Skill 页面，不应接触敏感技术配置。
- 系统管理页面后续应受管理员权限控制。
- API Key、Token、数据库密码等敏感字段永不明文回显。
- 停用被引用 MCP 前，后续真实实现必须展示影响 Skill 并二次确认。
- Skill/MCP 测试需要记录操作者、时间、输入摘要和结果。
- 页面不得提供任意代码执行入口。

## 19. 当前原型边界

### 19.1 已连接真实能力

- ChatBI 会话查询、创建、重命名、删除和置顶。
- ChatBI SSE 流式问答。
- Skill 路由结果和 MCP 执行步骤展示。

### 19.2 当前仅为前端原型状态

- Skill 安装状态。
- Skill/MCP 启停。
- Skill 工作流步骤调整。
- Skill/MCP 配置保存。
- Skill/MCP 测试。
- MCP 健康检查。
- Skill 使用次数统计。
- 新建 Skill 和接入 MCP。

### 19.3 原型状态限制

- 数据主要来自 `managementData.ts`。
- 写操作仅更新 React 内存状态。
- 刷新页面后状态可能重置。
- 当前无真实权限和审计记录。

## 23. 风险与注意事项

- 当前 Python 注册表与在线可编辑配置之间尚无持久化发布机制。
- Skill 工作流参数引用属于 DSL，真实编辑器需要严格校验。
- MCP 停用可能影响多个 Skill，后端必须提供依赖检查和原子操作。
- Skill 安装状态需要明确是用户级、角色级还是组织级。
- 使用次数统计需要定义调用口径、时间范围和失败调用是否计数。
- 商店精选和分类需要后续运营配置能力，不能长期写死在前端。
- 技术管理页面涉及敏感配置，必须接入安全存储和权限审计。
