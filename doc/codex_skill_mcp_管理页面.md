# codex_skill_mcp_管理页面

> 文档类型：产品需求文档（PRD）与前端原型规划  
> 文档状态：V0.1 草案，待评审  
> 创建日期：2026-06-10  
> 适用范围：ChatBI 对话页、Skill 管理页、MCP 管理页的统一产品与前端 UI

## 1. 项目背景

当前系统已经具备一套可运行的 ChatBI 对话页面，并通过 Skill + MCP 双层架构完成业务能力路由、工作流执行、内部数据查询、联网检索和结果分析。

现阶段系统的 Skill 与 MCP 主要通过 Python 配置文件、注册表和环境变量维护，缺少面向产品使用者的统一管理界面。随着 Skill、MCP 和配置项持续增加，仅依赖代码维护会带来以下问题：

- 使用者无法快速了解系统当前具备哪些能力、哪些能力可用。
- Skill 与 MCP 的依赖关系不直观，问题定位依赖阅读代码和日志。
- 新增、编辑、启停、测试配置的操作门槛较高。
- ChatBI 对话、能力配置、工具运维分散，缺少统一产品入口。

因此，本阶段需要将现有 ChatBI 对话页与新增的 Skill 管理页、MCP 管理页融合为一个统一的 ChatBI 系统工作台。

## 2. 产品目标

### 2.1 核心目标

构建一个统一的 ChatBI Web 工作台，让用户可以在同一套产品中完成：

1. 使用 ChatBI 发起问答并查看真实 Skill/MCP 执行链路。
2. 查看、筛选、创建、编辑、启停和测试 Skill。
3. 查看、筛选、创建、编辑、启停和测试 MCP。
4. 从 Skill 快速追踪其依赖的 MCP，从 MCP 快速查看被哪些 Skill 使用。
5. 使用统一的视觉、状态和交互规范管理整个智能能力体系。

### 2.2 第一阶段成功标准

- 三个一级页面可通过统一导航无刷新切换。
- Skill 管理页和 MCP 管理页具备完整的前端原型交互。
- 页面可展示当前仓库内已注册的 6 个 Skill 和 7 个 MCP。
- Skill/MCP 的详情、配置、测试、启停操作均有明确的 UI 和状态反馈。
- 对高风险配置提供校验、二次确认和敏感信息保护。
- 原型结构可直接承接后续真实 API 开发，不需要推翻重做。

### 2.3 非目标

第一阶段暂不包含：

- 完整的多租户、组织、角色与细粒度权限系统。
- 在线编写和执行任意 Python 代码。
- MCP 市场、Skill 商店、计费和审批中心。
- 工作流多人协作、版本分支和复杂发布流水线。
- 生产级密钥托管系统。

## 3. 当前能力基线

### 3.1 现有 ChatBI 页面

当前生产 Web 前端位于 `web_frontend/`，采用 React + TypeScript + Vite，已经具备：

- 历史会话、新建、置顶、重命名和删除。
- ChatBI 问答与 SSE 流式输出。
- 联网搜索开关。
- Skill 路由结果展示。
- MCP 执行步骤、入参、出参、耗时和错误展示。
- 数据表、ECharts 图表与分析文本渲染。

### 3.2 当前内置 Skill

## 4. 用户角色与核心场景

### 4.1 目标角色

| 角色 | 主要诉求 |
|---|---|
| 业务用户 | 使用 ChatBI 问答，理解系统调用了什么能力 |
| 产品/运营管理员 | 管理 Skill 的描述、示例、启停状态和工作流 |
| AI 应用开发者 | 配置 Skill 与 MCP，调试参数与执行结果 |
| 系统运维人员 | 检查 MCP 连通性、错误、依赖和运行状态 |

### 4.2 核心使用场景

1. 用户在 ChatBI 页面提出问题，查看系统选择的 Skill 和执行 MCP。
2. 管理员发现某个回答链路不合理，跳转到对应 Skill 查看流程配置。
3. 开发者修改 Skill 的步骤编排，在测试面板输入问题并验证结果。
4. 运维人员检查 MCP 的连接状态、配置完整性和最近错误。
5. 管理员停用异常 MCP，系统同时提示受影响的 Skill。
6. 用户创建新的 Skill，选择已有 MCP 组成工作流并保存草稿。

## 5. 信息架构

### 5.1 推荐方案：统一工作台 + 三个一级页面

采用统一应用外壳，将三个页面组织为同一个 ChatBI 系统：

```text
ChatBI 工作台
├── 智能问答
│   ├── 历史会话
│   ├── 消息与结果
│   └── Skill/MCP 执行链路
├── Skill 管理
│   ├── Skill 列表
│   ├── Skill 详情与编辑
│   ├── 工作流编排
│   └── Skill 测试
└── MCP 管理
    ├── MCP 列表
    ├── MCP 详情与配置
    ├── Schema 与连接设置
    └── MCP 测试与健康检查
```

### 5.2 方案对比

| 方案 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| A. 统一侧边导航工作台 | 三个一级页面共用应用壳层 | 产品感完整、扩展性好、三页关系清楚 | 需要调整现有 Chat 页外层布局 |
| B. Chat 页内增加管理抽屉 | Skill/MCP 以抽屉或弹窗出现 | 改动较小 | 管理复杂配置时空间不足，长期难扩展 |
| C. 三个独立站点 | 页面各自独立 | 开发解耦 | 用户体验割裂，状态与视觉容易不一致 |

**产品决策：采用方案 A。**

## 6. 全局产品框架

### 6.1 页面布局

桌面端使用“窄全局导航 + 页面内容区”的布局：

```text
┌──────────┬──────────────────────────────────────────────┐
│ 品牌区   │ 页面标题 / 全局状态 / 页面操作              │
├──────────┼──────────────────────────────────────────────┤
│ 智能问答 │                                              │
│ Skill管理│                  页面内容                    │
│ MCP管理  │                                              │
│          │                                              │
│ 系统状态 │                                              │
└──────────┴──────────────────────────────────────────────┘
```

全局导航建议宽度为 76px 收起态、216px 展开态。默认展开，支持手动收起。

### 6.2 全局导航

| 导航项 | 图标语义 | 页面 |
|---|---|---|
| 智能问答 | 对话气泡 | ChatBI 对话页 |
| Skill 管理 | 流程/能力节点 | Skill 管理页 |
| MCP 管理 | 工具/连接器 | MCP 管理页 |
| 系统状态 | 状态圆点 | 后续扩展入口，第一阶段只展示摘要 |

### 6.3 全局状态规范

所有 Skill 与 MCP 统一使用以下状态：

| 状态 | 含义 | UI 表现 |
|---|---|---|
| 已启用 | 可参与路由或被调用 | 绿色状态点 |
| 已停用 | 不参与路由或调用 | 灰色状态点 |
| 配置异常 | 缺少配置或校验失败 | 红色状态点 |
| 测试中 | 正在执行测试 | 蓝色加载状态 |
| 草稿 | 尚未发布 | 黄色标签 |

### 6.4 视觉方向

延续现有 ChatBI 页面视觉，不重新设计品牌风格：

- 背景：浅灰蓝页面背景与白色卡片。
- 品牌强调：延续现有红色强调色。
- 卡片：圆角、细边框、轻阴影。
- 状态：使用低饱和状态色和文字标签，不只依赖颜色。
- 代码与 Schema：使用等宽字体、深浅分层和复制按钮。
- 复杂编辑：优先使用右侧详情抽屉或独立详情页，不堆叠多层弹窗。

## 7. 页面一：智能问答

### 7.1 页面定位

保留现有 ChatBI 对话能力，主要调整其在统一工作台中的外层布局，并增强与 Skill/MCP 管理页的联动。

### 7.2 页面结构

- 左侧：现有历史会话面板。
- 中间：消息列表、结果和思考过程。
- 底部：输入框、联网开关与发送按钮。
- 顶部：当前会话信息与运行状态。

### 7.3 新增联动能力

- Skill 标签可点击，跳转至对应 Skill 详情。
- MCP 执行步骤中的 MCP 名称可点击，跳转至对应 MCP 详情。
- 错误步骤提供“查看 MCP 配置”入口。
- 对话完成后可将本轮问题带入 Skill 测试面板进行复现。

### 7.4 验收要点

- 原有聊天主链路不回归。
- 加入全局导航后，聊天可用空间仍然充足。
- 页面跳转时保留当前会话与消息状态。

## 8. 页面二：Skill 管理

### 8.1 页面定位

Skill 管理页用于管理业务能力与工作流编排。用户关注的是“这个能力解决什么问题、何时被路由、调用哪些 MCP、执行步骤是什么、当前是否可用”。

### 8.2 Skill 列表页

#### 页面头部

- 标题：Skill 管理。
- 摘要：Skill 总数、已启用、草稿、异常数量。
- 主操作：新建 Skill。

#### 筛选与搜索

- 按名称、描述搜索。
- 按分类筛选。
- 按状态筛选。
- 按依赖 MCP 筛选。
- 排序：最近更新、名称、调用次数。

#### 列表展示

第一阶段推荐使用卡片列表，而不是纯表格。每张 Skill 卡片展示：

- 中文显示名称与唯一标识。
- 描述、分类和输出类型。
- 状态与最近更新时间。
- 使用的 MCP 标签。
- 工作流步骤数量。
- 最近测试结果。
- 操作：查看、编辑、复制、启停、测试、更多。

### 8.3 Skill 详情与编辑

Skill 详情采用独立详情页，分为四个 Tab：

#### Tab 1：概览

- 基础信息：名称、标识、描述、分类、输出类型。
- 状态、版本、最近更新时间。
- 依赖 MCP 与依赖状态。
- 示例问题。
- 最近运行摘要与错误摘要。

#### Tab 2：工作流

采用纵向步骤编排原型，每个步骤卡片展示：

- 步骤序号、名称和描述。
- 绑定 MCP。
- arguments 参数映射。
- 输入变量与上游输出引用。
- 启用状态。
- 操作：编辑、复制、删除、上移、下移。

第一阶段前端原型支持新增步骤、拖动排序和配置表单；暂不实现复杂画布连线。

#### Tab 3：Schema 与原始配置

- `inputSchema` 可视化表单。
- JSON 配置编辑器。
- JSON 格式化、复制和校验。
- 可视化表单与 JSON 编辑器双向切换。

#### Tab 4：测试

- 输入测试问题或结构化参数。
- 选择是否开启联网。
- 执行测试。
- 展示 Skill 选择结果、步骤时间线、MCP 入出参、最终输出和错误。
- 支持“将结果带到智能问答页”。

### 8.4 新建 Skill 流程

采用三步向导：

1. 基础信息：名称、标识、分类、描述、输出类型。
2. 工作流配置：选择 MCP、添加步骤、配置参数映射。
3. 校验与测试：Schema 校验、依赖检查、试运行、保存草稿或启用。

### 8.5 Skill 关键校验

- Skill 唯一标识不可重复。
- 至少包含一个有效步骤。
- 每个步骤绑定的 MCP 必须存在且已启用。
- 参数引用必须符合 `{{input.xxx}}` 或 `{{steps.xxx.output}}` 规范。
- 停用 Skill 前提示其不会再参与自动路由。
- 删除第一阶段不做物理删除，改为归档。

## 9. 页面三：MCP 管理

### 9.1 页面定位

MCP 管理页用于管理原子工具、连接配置、输入 Schema、健康状态和依赖关系。用户关注的是“这个工具做什么、如何调用、配置是否完整、是否可用、被哪些 Skill 使用”。

### 9.2 MCP 列表页

#### 页面头部

- 标题：MCP 管理。
- 摘要：MCP 总数、已启用、异常、被 Skill 使用数量。
- 主操作：接入 MCP。
- 次操作：全部健康检查。

#### 筛选与搜索

- 按名称、描述搜索。
- 按分类筛选。
- 按状态筛选。
- 按是否被 Skill 使用筛选。
- 排序：健康状态、最近测试、名称。

#### 列表展示

第一阶段推荐使用紧凑表格，便于快速检查工具状态。字段包括：

| 字段 | 说明 |
|---|---|
| MCP | 显示名称、唯一标识、描述 |
| 分类 | AI、Database、Retrieval、Utility 等 |
| 状态 | 已启用、已停用、配置异常 |
| 健康检查 | 最近一次结果与时间 |
| 被引用 | 使用该 MCP 的 Skill 数量 |
| 配置来源 | 内置、本地、自定义 |
| 操作 | 查看、配置、测试、启停、更多 |

### 9.3 MCP 详情与配置

MCP 详情采用独立详情页，分为四个 Tab：

#### Tab 1：概览

- 名称、标识、描述、分类。
- 当前状态和最近健康检查。
- 配置来源与运行模式。
- 被哪些 Skill 引用。
- 最近执行次数、成功率、平均耗时。第一阶段使用 mock 指标占位。

#### Tab 2：连接与配置

- 环境与连接参数表单。
- 敏感字段默认掩码，仅展示是否已配置。
- 配置校验和连接测试。
- 不在浏览器回显 API Key、密码等真实值。

针对现有 MCP 展示不同配置组：

- `llm`：模型名称、Base URL、温度、最大 Token、API Key 状态。
- `sql_executor`：数据库连接状态、允许表、最大行数、超时。
- `knowledge_retrieval`：Dify 地址、数据集、启用状态。
- `web_search`：Provider、Base URL、Top K、超时、API Key 状态。
- `time`、`text_analysis` 等本地工具：展示运行说明，无敏感配置。

#### Tab 3：Schema

- `inputSchema` 可视化字段表。
- 字段名称、类型、必填、默认值、枚举和描述。
- JSON 编辑器、格式化、复制和校验。
- 显示标准返回契约：`success`、`data`、`error`、`error_type`。

#### Tab 4：测试与日志

- 根据 `inputSchema` 自动生成测试表单。
- 执行 MCP 测试。
- 展示输入 JSON、输出 JSON、耗时、状态和错误。
- 展示最近测试记录。第一阶段只在前端保留当前会话记录。

### 9.4 接入 MCP 流程

采用三步向导：

1. 基础信息：名称、标识、分类、描述、接入类型。
2. Schema 与配置：填写 `inputSchema`，配置连接参数。
3. 测试与启用：连接校验、试运行、保存草稿或启用。

第一阶段支持两种接入类型的 UI 原型：

- 本地注册 MCP：对应当前 Python 注册表模式。
- 远程标准 MCP：预留 Server URL、Transport、认证方式等配置字段。

### 9.5 MCP 关键校验

- MCP 唯一标识不可重复。
- `inputSchema` 必须是合法 JSON Schema。
- 停用被引用的 MCP 时，必须展示受影响 Skill 并二次确认。
- 配置异常的 MCP 不允许启用。
- 敏感字段不可在列表、日志和详情页明文展示。
- 第一阶段不允许从页面执行任意代码。

## 10. 三页融合与跨页联动

### 10.1 核心联动

| 来源 | 操作 | 目标 |
|---|---|---|
| 智能问答 | 点击已选 Skill | 打开 Skill 详情 |
| 智能问答 | 点击执行步骤 MCP | 打开 MCP 详情 |
| Skill 详情 | 点击依赖 MCP | 打开 MCP 详情 |
| MCP 详情 | 点击引用 Skill | 打开 Skill 详情 |
| Skill 测试 | 带入问题 | 跳转智能问答并预填输入 |
| MCP 异常 | 查看影响 | 展示依赖 Skill 列表 |

### 10.2 状态一致性

- Skill 被停用后，不再参与 ChatBI 自动路由。
- MCP 被停用后，不允许新的 Skill 启用并引用该 MCP。
- MCP 配置异常时，依赖 Skill 显示“依赖异常”状态。
- 页面内修改未保存时，切换页面需弹出离开确认。

## 11. 前端原型范围

### 11.1 本轮需要完成

- 统一应用壳层与全局导航。
- 现有 ChatBI 页适配统一壳层。

- 桌面端主要分辨率适配，最低建议宽度 1280px。

### 11.2 本轮原型不接真实写入

以下操作第一阶段使用前端 mock 状态完成交互闭环：

- 创建、编辑、复制、归档 Skill。
- 修改 Skill 工作流。
- 接入、编辑、停用 MCP。
- 运行健康检查和测试。
- 运行指标和日志。

保留现有真实 ChatBI 对话 API，不影响已完成的问答主链路。

## 12. 建议前端技术方案

### 12.1 路由与页面

## 14. 权限与安全原则

第一阶段原型需要体现权限与安全设计，即使暂不接真实权限系统：

- 普通用户只可访问智能问答。
- 管理员可进入 Skill/MCP 管理页面。
- 查看、编辑、测试、启停操作应有不同权限语义。
- API Key、数据库密码、Token 等敏感字段永不明文回显。
- 停用 MCP、归档 Skill 等高风险操作必须二次确认。
- 测试执行需要记录操作者、时间、输入摘要和结果状态。
- 页面不得提供任意 Python 代码执行入口。

## 15. 空状态、错误与反馈

| 场景 | UI 反馈 |
|---|---|
| 无搜索结果 | 提供清除筛选按钮 |
| Skill 无步骤 | 引导添加第一个步骤 |
| MCP 无引用 | 提示当前尚未被 Skill 使用 |
| Schema 校验失败 | 定位到具体字段与错误原因 |
| 测试失败 | 自动展开错误详情并提供重试 |
| 停用被引用 MCP | 展示受影响 Skill 并二次确认 |
| 配置未保存 | 离开页面前确认 |
| API 不可用 | 页面保留已有数据并显示顶部错误提示 |

### 16.1 全局

- 三个一级页面均能从全局导航进入。
- 页面视觉与现有 ChatBI 风格一致。
- 所有主要操作具备 hover、active、disabled、loading 和 error 状态。

- Chat 页点击 MCP 步骤可进入对应详情。
- 从管理页返回 Chat 页时，原会话状态不丢失。

## 18. 风险与待确认项

### 18.1 已识别风险

- 当前 Skill/MCP 由 Python 导入注册，真实在线编辑需要设计持久化与发布机制。
- 启停 MCP 会影响多个 Skill，后端必须提供依赖校验。
- Skill 流程参数引用存在 DSL 规则，前端编辑器需要严格校验。
- 远程标准 MCP 与当前本地 Python MCP 的配置模型不同，需保留扩展空间。
- 配置页面涉及敏感凭据，后续真实实现必须接入安全存储。

### 18.2 本 PRD 默认决策

- 第一阶段只做前端原型与 UI，不改动现有 Skill/MCP 执行逻辑。
- Skill 工作流采用纵向步骤编排，不做复杂节点画布。
- Skill 使用卡片列表，MCP 使用紧凑表格。
- 三页通过统一左侧导航融合。
- 当前 6 个 Skill 和 7 个 MCP 作为原型首批数据。
- 管理页写操作使用 mock 状态，Chat 页继续连接现有真实 API。
